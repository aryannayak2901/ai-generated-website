# Frontend Theme Alignment — Direct Token Replacement Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every hardcoded legacy Tailwind token (`bg-charcoal-primary`, `bg-teal-primary`, `text-slate-secondary`, etc.) in all 38+ frontend components and UI primitives with the correct semantic Tailwind token that maps to the CMS-generated CSS variables, so that theme changes in Payload CMS are instantly reflected on the live website.

**Architecture:** All components will use Tailwind v4 semantic utility classes (`bg-primary`, `bg-accent`, `text-accent`, `text-muted-foreground`, `bg-secondary`) that are wired to `--primary`, `--accent`, `--muted-foreground`, `--secondary` CSS variables in `globals.css`. These CSS variables are overridden at runtime by `/public/theme-overrides.css` which is regenerated by Payload CMS hooks on every theme save. No aliasing layer — components reference semantic tokens directly.

**Tech Stack:** Next.js 15, Tailwind CSS v4, Payload CMS, TypeScript
