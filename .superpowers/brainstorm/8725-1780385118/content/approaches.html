Proposed Technical Architecture

Here are the two architectural approaches for adding multiple headers and live preview in Payload CMS.

1

(Recommended) Integrated Global Header Preview

We extend the existing Header global config with custom controls (style dropdown, toggles, text fields) and mount a custom HeaderPreview React component at the top of the form.

How it works: The custom preview uses useForm() from Payload UI to watch form state in real time. As logo, links, or styles are updated, the preview re-renders instantly before saving.
Pros: Zero database complexity, extremely intuitive, fast performance, inherits existing global data.
Cons: None. It perfectly aligns with the current codebase structure.
2

Multi-Header Collection

Convert the Header config from a single Global into a collection of multiple header styles. The user creates separate header documents (e.g., "Classic Layout", "Modern Glass Layout") and chooses an active one in a global setting.

Pros: Allows maintaining multiple independent headers and scheduling/switching them instantly.
Cons: Over-complicates the CMS setup. Increases DB reads, database relationships, and makes live updates across layouts more disjointed.
